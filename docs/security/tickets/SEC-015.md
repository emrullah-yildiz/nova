## Gap
The production deployment is the Cloudflare Worker (`worker/index.mjs`), which
serves SPA assets and API responses with **no `Strict-Transport-Security`
(HSTS)** and none of the other hardening headers. The legacy node server
(`src/enterprise/api-server.mjs`) does set `X-Content-Type-Options: nosniff` and
`X-Frame-Options: DENY`, but that server is **not the deployed target** (Cloudflare
Worker only, per decisions.md), so those protections do not apply in production.

## Why it matters (user-rights impact)
HSTS instructs browsers to only ever connect over HTTPS, defending against SSL-
strip / downgrade attacks on a user's session and project data. Its absence
leaves transport security entirely to Cloudflare's edge defaults with no
app-asserted policy. This pairs with SEC-010 (no CSP) — together they are the
standard web hardening header set, currently absent from the deployed Worker.

## Evidence
- `worker/index.mjs:162-168` default `fetch` returns `env.ASSETS.fetch(request)`
  and API responses via `app.fetch` with no added security headers.
- `api/proxy/chat.mjs` `corsHeaders` and `worker/api.mjs` `cors` set only CORS /
  cache headers — no HSTS / nosniff / frame headers.
- Hardening headers exist only in the non-deployed `src/enterprise/api-server.mjs:127-128`.

## Recommended action / acceptance criteria
- CODE: add `Strict-Transport-Security: max-age=…; includeSubDomains`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, and frame protections to
  Worker responses (coordinate the CSP/frame-ancestors with SEC-010).
- Acceptance: production responses carry HSTS and nosniff; verified against
  `hi-nova.work`.
