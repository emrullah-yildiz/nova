## Gap
The production deployment is the Cloudflare Worker (`worker/index.mjs`), which
serves SPA assets and API responses with **no `Strict-Transport-Security`
(HSTS)** and none of the other hardening headers. The legacy node server
(`src/enterprise/api-server.mjs`) does set `X-Content-Type-Options: nosniff` and
`X-Frame-Options: DENY`, but that server is **not the deployed target** (Cloudflare
Worker only, per decisions.md), so those protections do not apply in production.

## Why it matters (user-rights impact)
HSTS instructs browsers to only ever connect over HTTPS, defending against SSL-
strip / downgrade attacks on a user's session and project data. Its absence
leaves transport security entirely to Cloudflare's edge defaults with no
app-asserted policy. This pairs with SEC-010 (no CSP) — together they are the
standard web hardening header set, currently absent from the deployed Worker.

## Evidence
- `worker/index.mjs:162-168` default `fetch` returns `env.ASSETS.fetch(request)`
  and API responses via `app.fetch` with no added security headers.
- `api/proxy/chat.mjs` `corsHeaders` and `worker/api.mjs` `cors` set only CORS /
  cache headers — no HSTS / nosniff / frame headers.
- Hardening headers exist only in the non-deployed `src/enterprise/api-server.mjs:127-128`.

## Recommended action / acceptance criteria
- CODE: add `Strict-Transport-Security: max-age=…; includeSubDomains`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, and frame protections to
  Worker responses (coordinate the CSP/frame-ancestors with SEC-010).
- Acceptance: production responses carry HSTS and nosniff; verified against
  `hi-nova.work`.

## References
GDPR Art. 32 (security in transit); OWASP ASVS V14.4 (HTTP security headers);
`worker/index.mjs`; `src/enterprise/api-server.mjs` (the headers that aren't
deployed).

## Resolution
Resolved on branch `feat/sec-015-hsts` (off `develop`).

SEC-010 had already shipped `worker/security-headers.mjs` (CSP + nosniff +
Referrer-Policy + X-Frame-Options/frame-ancestors) with a wired `{ hsts }` option,
applied to every asset response in `worker/index.mjs` via
`applySecurity(res, { hsts: env.NOVA_HSTS === '1' })`. This ticket enabled and
finalized HSTS for production:

- `worker/security-headers.mjs` — finalized the HSTS string to
  `Strict-Transport-Security: max-age=63072000; includeSubDomains` (2y). Dropped
  the stub's `preload` directive: HSTS preload-list submission is a
  near-irreversible commitment that every current/future `hi-nova.work` subdomain
  is HTTPS-only forever, which we can't guarantee — `max-age + includeSubDomains`
  gives the downgrade/SSL-strip protection without that lock-in.
- `wrangler.toml` — set `NOVA_HSTS = "1"` in the top-level `[vars]` (production,
  → `hi-nova.work`) and `NOVA_HSTS = "0"` in `[env.dev.vars]` (dev runs on
  workers.dev / may be plain HTTP locally; env vars don't inherit from the
  top-level block, so dev is explicitly off). SEC-012's per-env KV namespace
  structure untouched.
- nosniff / Referrer-Policy / frame-ancestors (SEC-010) remain present on prod
  responses; `Headers.set` overwrites, so no duplication.

Test: `tests/sec-015-hsts.test.js` — asserts `securityHeaders({ hsts: true })`
emits exactly `max-age=63072000; includeSubDomains` (and never `preload`), that
default / `{ hsts: false }` omit the header, the `hstsMaxAge` override, and that
`applySecurity({ hsts: true })` adds HSTS alongside the SEC-010 headers with no
duplication.

Validation: ESLint clean on the changed files; full suite green (1599 passed,
1 skipped). `wrangler deploy --dry-run` confirmed `env.NOVA_HSTS ("1")` for prod
and `("0")` for `--env dev`.

Residual: none — `needs: code` is fully satisfied. (The `affected` list mentions
the CORS helpers in `api/proxy/chat.mjs` / `worker/api.mjs`; HSTS belongs on the
HTML/asset responses, which all flow through `applySecurity`, so no change is
needed there. The legacy `src/enterprise/api-server.mjs` is not the deployed
target and is out of scope.)
