## Gap
The Worker serves the SPA via the ASSETS binding with **no security headers** —
no `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, or
`X-Frame-Options`. The UI also constructs markup via `innerHTML` in multiple
places (e.g. AI chat rendering), and the AI renders model- and user-derived
content. Combined with plaintext API keys in localStorage (SEC-008), an XSS would
be high-impact.

## Why it matters (user-rights impact)
A CSP is the primary defence-in-depth control against XSS and data exfiltration.
Its absence means any reflected/stored/AI-injected script executes with full
origin privileges: it can read localStorage (BYOK keys), drive authenticated API
calls (the session cookie is HttpOnly so the token itself isn't readable — good —
but the script can still act as the user), and exfiltrate project data.

## Why it matters (user-rights impact, cont.)
The session cookie being HttpOnly/Secure/SameSite=Lax (`worker/cookies.mjs`)
correctly prevents token theft via JS, but does not prevent an XSS from acting on
the user's behalf.

## Evidence
- `worker/index.mjs:162-168` default export serves `env.ASSETS.fetch(request)`
  with no added response headers (no CSP).
- innerHTML-based rendering: `rg -n "innerHTML" src/ai/gpt-integration.js` and
  across `src/ui/**` (model/user content rendered into the DOM).
- BYOK keys in localStorage amplify impact: `src/ai/gpt-client.js:1132,1138`
  (see SEC-008).

## Recommended action / acceptance criteria
- CODE: add a strict `Content-Security-Policy` (and `X-Content-Type-Options:
  nosniff`, `Referrer-Policy`, `X-Frame-Options`/`frame-ancestors`) to SPA
  responses in the Worker; allow only the needed AI provider origins for
  `connect-src` (Groq/Gemini/Anthropic/OpenRouter for BYOK).
- CODE: audit `innerHTML` sinks that render model/user content; sanitize or
  switch to textContent / a trusted renderer for untrusted strings.
- Acceptance: responses carry a CSP that blocks inline/3rd-party script by
  default; AI/user content cannot inject executable markup.

## Resolution
Resolved on branch `feat/sec-010-csp-headers` (off `develop`).

**Headers (new `worker/security-headers.mjs`, wired in `worker/index.mjs`).**
Static SPA/asset responses from the `env.ASSETS` binding are now passed through
`applySecurity()`, which merges a Content-Security-Policy plus
`X-Content-Type-Options: nosniff`, `Referrer-Policy:
strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, and
`X-Permitted-Cross-Domain-Policies: none` onto the response while preserving its
Content-Type/ETag/body/status. The helper is the single hardening extension
point: SEC-015 can enable HSTS without touching call sites — `applySecurity` is
already invoked with `{ hsts: env.NOVA_HSTS === '1' }`, so setting the
`NOVA_HSTS` Worker var to `1` (prod, HTTPS) emits
`Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`.

**CSP shipped:**
```
default-src 'self';
script-src 'self' 'unsafe-inline' https://cdnjs.cloudflare.com https://cdn.jsdelivr.net;
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src 'self' https://fonts.gstatic.com;
img-src 'self' data: blob:;
connect-src 'self' https://api.openai.com https://api.groq.com https://generativelanguage.googleapis.com https://api.anthropic.com https://openrouter.ai ws://127.0.0.1:* ws://localhost:* wss:;
object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'
```
It allows everything the SPA legitimately loads (verified against the built
`dist/index.html`: self JS/CSS, the three.js CDNs, Google Fonts CSS + gstatic
font files, data:/blob: chat thumbnails), the five BYOK AI provider origins, and
the Nova Connect / Revit hub WebSocket in `connect-src`, while blocking arbitrary
external script (`script-src` is a tight
allow-list, no bare `https:`, no `'unsafe-eval'`), plugin/object script, `<base>`
hijack, and framing/clickjacking (`frame-ancestors 'none'` + `X-Frame-Options`).

**innerHTML audit.** The AI/user-content render path is already safe: AI response
prose goes through `app.fmt()` (`src/app/app.js`), which HTML-escapes via
`escapeHtml()` *before* applying its lightweight markdown, so model- or
user-injected `<script>`/`<img onerror>` is neutralised; chat attachment names
and image data-URLs are escaped via `_escHtml` (`src/ai/gpt-integration.js`);
user messages use `textContent`; and the node-renderer collaborator/file-name
sinks were escaped in prior work. No unescaped untrusted sink remained, so no
new escaping was required — a regression test now pins the `fmt` behaviour.

**Tests** (`tests/sec-010-security-headers.test.js`): CSP present with
`frame-ancestors 'none'` / `object-src 'none'` / `base-uri 'self'`, no
`'unsafe-eval'`, no bare `https:` in `script-src`; nosniff + Referrer-Policy +
`X-Frame-Options: DENY`; all five AI origins in `connect-src`; the Nova Connect /
Revit hub WebSocket origins (`ws://127.0.0.1:*` / `ws://localhost:*` / `wss:`) in
`connect-src`; self assets, fonts and CDNs allowed; HSTS off by default and only
with `{ hsts: true }`;
`applySecurity` preserves body/status/Content-Type/ETag; and `app.fmt` escapes
injected markup.

**Validation:** `eslint .` clean; full vitest suite 1573 passed / 1 skipped;
`vite build` OK; built `dist/index.html` references only CSP-allowed origins.

**Residual (documented compromise):** `script-src` and `style-src` include
`'unsafe-inline'` because `index.html` ships dozens of inline event handlers
(`onclick=`, `oninput=`, …) and inline `style=""` attributes. A nonce/hash
strategy would require rewriting that markup (and is ignored by browsers once a
nonce/hash is present), so `'unsafe-inline'` is the least-permissive option that
keeps the app working. Same-origin inline handlers are therefore permitted, but
arbitrary *external* script injection and framing are still blocked, and the
primary XSS vector (AI/user content) is escaped at the sink. Tightening to a
nonce-based CSP is a follow-up that depends on de-inlining the SPA's handlers.
No legal/policy `needs:` remain.
