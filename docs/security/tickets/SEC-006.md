## Gap
Audit events are stored as an array (`auditEvents`) inside the same in-memory
EnterpriseStore snapshot that is serialized as one blob to Neon and rewritten on
every mutation (`exportSnapshot`/`writeSnapshot`). Consequences:
1. **Not tamper-resistant / not append-only.** Any code path that rewrites the
   snapshot rewrites the audit log; there is no separate, write-once audit store.
2. **Deleted with their subject.** `deleteProject`/`deleteUserAccount` remove the
   records but the audit log of *who did what* is itself mutable in the same
   blob, so the trail can be lost on a bad write or rollback.
3. **No retention policy.** `auditEvents` grows unbounded; there is no documented
   retention or rotation (also a Neon storage risk, per decisions.md).
4. **PII in the trail.** Audit metadata/login events carry `userId` and (via
   account flows) email, with no minimization.

## Why it matters (user-rights impact)
Art. 5(2) (accountability) and Art. 32 (security of processing) call for a
reliable record of security-relevant events (auth, permission changes, data
export/delete, approvals). A mutable, blob-embedded log that is rewritten on
every request and can vanish with a snapshot write is not a dependable audit
trail, and an unbounded PII-bearing log over-retains personal data.

## Evidence
- `src/enterprise/domain.mjs:1160` `audit()` pushes to `this.auditEvents` then
  `this.persist()` (full-snapshot rewrite).
- `:1187` `exportSnapshot` includes `auditEvents` in the single blob;
  `worker/api.mjs` comment (lines 5–8) confirms "in-memory store with snapshot
  persistence … reads the full snapshot per cold isolate and flushes on writes."
- `:142,158` login events store `userId`; account flows store email in metadata.

## Recommended action / acceptance criteria
- CODE: move audit events to an append-only sink separate from the mutable
  snapshot (a dedicated table / log stream), so a snapshot rewrite cannot mutate
  or drop history.
- POLICY/PROCESS: define an audit retention period and a minimization rule
  (e.g. store userId reference, not raw email; anonymize on erasure per SEC-004).
- CODE: bound growth (rotation/retention enforcement) to respect the Neon budget
  noted in decisions.md ("Neon Stores Relational Data").
- Acceptance: audit records survive unrelated snapshot writes; retention + PII
  policy documented and enforced.
