## Gap
The only rate limiter in the deployed stack is the per-IP AI-proxy limiter
(`worker/index.mjs` `checkRate`). The authentication routes — `/api/auth/login`,
`/api/me/password`, `/api/auth/verify`, `/api/auth/resend-verification`,
`/api/auth/signup` — have **no rate limiting or lockout**. An attacker can submit
unlimited password guesses against `handleLogin` (PBKDF2 verify per attempt) and
unlimited verification-token guesses, bounded only by network speed.

## Why it matters (user-rights impact)
Art. 32 requires appropriate security of processing. Unthrottled login is the
textbook credential-stuffing / brute-force exposure (OWASP ASVS V2.2.1: anti-
automation on authentication). Although login uses a single generic error to
resist enumeration (good), an attacker can still mount online password attacks
and abuse the email-sending path (`resend-verification`) for spam/cost.

## Evidence
- `src/enterprise/api-dispatch.mjs:409` `handleLogin` — verifies password, no
  attempt counter / backoff.
- `src/enterprise/api-dispatch.mjs:312` `handleChangePassword`,
  `:256` `handleVerifyEmail`, `:270` `handleResendVerification` — no throttle.
- `worker/index.mjs` `checkRate` (lines 151–160) is invoked only inside the
  `/api/proxy/chat` handler; the `/api/*` enterprise dispatch path
  (`handleEnterpriseApi`) applies no limiter.

## Recommended action / acceptance criteria
- CODE: add a per-IP and per-account rate limit + exponential backoff/lockout to
  the auth routes, backed by the existing `RATE_KV` (reuse the `checkRate`
  pattern with auth-specific keys/limits). Cap `resend-verification` and signup
  per IP/email.
- CODE: add a test asserting repeated failed logins are throttled (429/lockout).
- Acceptance: N failed logins within a window are rejected before reaching
  PBKDF2 verify; verification-token guessing is rate-limited.

## References
GDPR Art. 32; OWASP ASVS V2.2.1 / V11.1; `src/enterprise/api-dispatch.mjs`;
`worker/index.mjs`; `worker/api.mjs`.

## Resolution
Resolved 2026-06-04 on `fix/sec-005-auth-rate-limit`.

A KV-backed auth throttle now guards the five authentication routes, applied in
the dispatcher **before** the handler runs (so PBKDF2 verify / email sends never
execute for an over-limit caller).

- **New helper** `worker/auth-rate-limit.mjs` exposes
  `checkAuthRate(env, { ip, accountKey, action }) -> { ok, retryAfterMs }` (plus
  `resetAuthRate(...)`). It reuses the AI-proxy `checkRate` KV-bucket pattern
  (one JSON bucket per key in `RATE_KV`, counter incremented per attempt, TTL =
  bucket reset) with **auth-specific** keys and per-action limits, checking a
  per-IP **and** per-account bucket. Over the limit → exponential lockout that
  doubles per strike up to a cap. With no `RATE_KV` bound (local dev / Node
  tests) it fails open, matching the proxy limiter.
  - login / change-password: 8/account, 20/IP per 15 min; lockout 30s → 1h.
  - verify (token guessing): 30/IP per 15 min (per-IP only — no account).
  - resend-verification / signup: 5/email + 10/IP per hour; lockout 60s → 6h.
- **Dispatcher** (`src/enterprise/api-dispatch.mjs`): `createApiDispatcher` takes
  an optional `rateLimiter`; auth routes resolve `{ action, accountKey }` and are
  throttled first, returning `429 RATE_LIMITED` with `retryAfterMs` when blocked.
  A successful `login` / `change-password` clears that account's bucket so a real
  user's earlier typos don't lock them out.
- **Worker wiring** (`worker/api.mjs`): builds the KV-backed limiter from `env`,
  passes the caller IP (`cf-connecting-ip`) into `dispatch`, and emits a standard
  `Retry-After` header on 429s. (`worker/index.mjs` already forwards the full
  `env`, incl. `RATE_KV`, to `handleEnterpriseApi`, so no change there.)

**Tests** — `tests/auth-rate-limit.test.js` (7 cases): the helper limits, locks
out, escalates the backoff across windows, and resets; verification-token
guessing is throttled per IP; and at the dispatch level, repeated failed logins
return `429` with **no further PBKDF2 verify** once over the limit, with the
correct password accepted again after a reset.
