## Gap
`parseXLSX`/`parseCSV` parse uploaded files (a recently-added feature) with the
SheetJS `xlsx` library and a hand-written CSV tokenizer, but apply **no upper
bound** on input size, number of sheets, rows, columns, or total cells. A
maliciously crafted or simply very large workbook (e.g. a "zip bomb"-style sheet
declaring an enormous used range, or a multi-hundred-MB CSV) can exhaust memory
or hang the tab.

## Why it matters (user-rights impact)
Parsing runs client-side on untrusted input. While the module commendably defends
against prototype pollution (null-prototype rows for `__proto__`/`constructor`
headers — good), it does not defend against resource exhaustion. A user opening a
hostile file (or a shared project that references one) can lose their unsaved
work to a frozen/crashed tab — an availability harm. SheetJS has a history of
parser CVEs (prototype pollution, ReDoS), so input must be bounded defensively.

## Evidence
- `src/data/spreadsheet-parse.js:329` `parseXLSX` calls `XLSX.read(...)` and
  `XLSX.utils.sheet_to_json(... header:1 ...)` with no size/dimension guard.
- `:156` `parseCSV` / `:68` `tokenizeCSV` iterate the whole string with no length
  cap.
- `src/ui/file-control.js` reads the file (no size check found there either).
- Dependency pinned: `xlsx@0.20.3` (current `npm audit` clean, but parser
  hardening is still warranted given the library's CVE history).

## Recommended action / acceptance criteria
- CODE: enforce a max upload byte size in `src/ui/file-control.js` before reading
  the file; reject oversized files with a clear message.
- CODE: cap rows/columns/total cells in `parseXLSX`/`parseCSV` (e.g. refuse > N
  rows or > M cells), and cap the input string length in `tokenizeCSV`.
- CODE: add tests for the limits (oversized file rejected; pathological sheet
  bounded).
- Acceptance: a file above the configured limits is rejected before it can hang
  the tab; limits are documented.

## Resolution
Resolved 2026-06-04 on branch `fix/sec-011-spreadsheet-bounds`.

Two complementary layers now bound untrusted spreadsheet/CSV input:

1. **Byte-size guard (pre-read), `src/ui/file-control.js`** — already present from
   the file-control work and reaffirmed: `fileToControlValue` rejects any file
   whose `file.size > MAX_FILE_BYTES` (**10 MB**) BEFORE reading or base64-encoding
   a single byte, with a clear "File too large …" error. (Covered by the existing
   file-control size-guard tests.)

2. **Parser-level dimension caps (new), `src/data/spreadsheet-parse.js`** — exported
   constants, enforced and documented in the module header:
   - `MAX_INPUT_CHARS` = **64M** chars — `tokenizeCSV` refuses an over-long input
     string before its O(n) scan.
   - `MAX_COLS` = **16384** — column/header count cap.
   - `MAX_ROWS` = **1,000,000** — data-row count cap (header excluded).
   - `MAX_CELLS` = **5,000,000** — rows×cols product cap (the dominant guard;
     catches "few rows × huge width" and "huge height × few cols" shapes a single
     dimension cap misses).
   - `parseCSV` enforces the row/col/cell caps after tokenizing, before building
     row objects.
   - `parseXLSX` enforces the caps against the worksheet's **declared range
     (`!ref`) BEFORE `sheet_to_json`**, so a "zip-bomb"-style sheet that merely
     *declares* an enormous used range is rejected without SheetJS materializing
     millions of cells; a post-parse backstop re-checks the actual returned shape.
   - All rejections throw a clear `Spreadsheet too large: <what> (<got>) exceeds
     the limit of <limit> …` error naming the breached limit.

**Tests** (`tests/data/spreadsheet-parse.test.js`, "resource bounds (SEC-011)"):
over-length CSV string rejected; CSV header over `MAX_COLS` rejected; XLSX sheet
declaring a pathological row range / column count / cell-count product rejected
(via a mocked reader returning a huge `!ref`); a normal small CSV and a normal
small real workbook still parse correctly; constants exported and ordered sanely.

**Validation:** `eslint .` clean; full `vitest run` green (1559 passed, 1 skipped;
43 in the spreadsheet-parse file including the 8 new bound tests).
