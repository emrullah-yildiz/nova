## Gap
Nova has `GET /api/me` (basic profile) and per-project export of graphs, but
**no consolidated data-subject access / export / rectification path**. There is
no endpoint or process that returns *everything* Nova holds about a user (profile,
memberships, projects, versions, AI request metadata, audit events referencing
them, invites) in a portable form, and no self-serve way to correct inaccurate
profile data beyond display name/password.

## Why it matters (user-rights impact)
GDPR Art. 15 (access), Art. 16 (rectification), and Art. 20 (portability) give
data subjects the right to obtain a copy of their data in a structured, commonly
used, machine-readable format and to correct it. Without a defined mechanism,
Nova cannot fulfil a DSAR within the one-month statutory window.

## Evidence
- Route table `src/enterprise/api-dispatch.mjs:35-121` has `GET /api/me`,
  per-project `GET .../versions`, `.../runs`, `.../artifacts`, but no
  user-scoped "export all my data" route and no rectification beyond
  `PUT /api/me/password`.
- `src/enterprise/domain.mjs` has `exportSnapshot()` (whole-store, admin/internal)
  but nothing user-scoped.

## Recommended action / acceptance criteria
- CODE: add an authenticated `GET /api/me/export` that assembles the requesting
  user's personal data (profile, memberships, owned projects + versions, AI
  request metadata, audit events where they are the subject) into a single JSON
  download.
- CODE: allow rectification of profile fields (name, email subject to
  re-verification) via `PUT /api/me`.
- PROCESS: document the DSAR handling procedure + SLA (one month) and who owns it.
- Acceptance: a signed-in user can download a machine-readable copy of their data;
  a documented manual fallback exists for fields not yet self-serve.
